## Хронология

### 1. Проверка звука в записи `D:\Video\recordly\2026-11-22 23-09-23.mkv`

  `D:\Projects\codex\remotion\node_modules\@remotion\compositor-win32-x64-msvc\` (ffmpeg урезанный:
  нет `volumedetect`, есть `silencedetect`).
- В файле видео AV1 и 5 аудиодорожек AAC, длительность 5:58.
- Анализ тишины (`silencedetect`, порог −50 dB):
  - Track 1: тишина все 358 с;
  - **Track 2: звук около 270 с, 62 паузы, похоже на речь**;

- Вывод: голос записался только на Track 2. Плееры по умолчанию играют Track 1, поэтому казалось,
  что звука нет.

### 2. Диагностика настроек OBS
Прочитаны конфиги профиля и коллекции сцен:
- режим вывода Advanced, формат MKV, запись дорожек 1–5;
- «Звук раб. стола» (`device_id: default`) → дорожки 1, 5;
- «Микро» (`device_id: default`) → дорожка 2;
- «Захват звука приложения (БЕТА)» → все дорожки, цель — поиск Windows.

Причины проблем:
1. звук системы не попал в запись (Track 1 и 5 пустые);
2. захват приложения ничего полезного не ловил и подмешивался в голосовую дорожку.

Пользователь хотел: **звук системы и микрофон на отдельных дорожках, чтобы голос обрабатывать отдельно.**

## Обсуждение идеи проекта

### 6. Озвучка через ElevenLabs
- Идея пользователя: заменить голос Windows на ElevenLabs (есть подписка), чтобы Claude сам записывал
  видео с голосом.
- Первый вариант Claude: записать экран, а голос наложить потом.
- Пользователь уточнил: нужна **живая озвучка прямо во время записи**, без наложения.
- Разобрано, как это сделать: фразы генерируются заранее, а во время записи цикл «фраза → действие».
  Проблемы: паузы на «раздумья», ошибки в эфире, смешение голоса со звуком системы (решается VB-Cable).

### 7. Как организовать без управления через скриншоты
- Модель не должна двигать мышь в реальном времени. Она пишет сценарий и код, а выполняет программа.
- Конвейер: сценарий (JSON) → озвучка (ElevenLabs API) → исполнитель (obs-websocket +
  Playwright / pywinauto) → видео. Для видео без записи экрана — Remotion.
- Роли: Opus в Claude Code (подписка) — построить и отлаживать; DeepSeek API — генерация сценариев пачками;
  скрипт — исполнение без токенов.

### 8. Адаптация к тому, что меняется на экране
- Уровень 1: дерево интерфейса (UI Automation, DOM) — поиск элементов по названию, а не по координатам.
- Уровень 2: «обучение точкам» = запись макросов (Playwright codegen, рекордеры для Windows).
- Уровень 3: ИИ со зрением только при сбоях. Готовые модели для экрана: OmniParser, UI-TARS.
  Обучать свою модель не нужно.

### 9. Агент, который сам принимает решения
- Экран переводится в текстовый список элементов, поэтому решать может дешёвая текстовая модель (DeepSeek).
- Два уровня: быстрый исполнитель на каждом шаге и сильный планировщик со зрением при застревании.
- Действия крупными блоками, реакция на события Windows вместо постоянных скриншотов.
- Голос в потоковом режиме звучит параллельно с действием и маскирует задержки.
- Готовые основы: browser-use, Microsoft UFO.

### 10. Pomerado (скриншот поста от пользователя)
- Инструмент превращает сайт в API/MCP: ИИ один раз изучает интерфейс, дальше вызовы идут без ИИ.
- Как устроено: разведка с записью сетевого трафика → генерация функций по внутренним запросам
  сайта → проверка и самоисправление → сохранение сессии (вход с 2FA один раз) → упаковка в MCP →
  выполнение без ИИ и переразведка при поломке.
- Сам репозиторий не открывался, разбор сделан по посту.

### 11. Обобщение на весь компьютер
Пять входов в программу, от надёжного к хрупкому:
1. собственное API (OBS websocket, Office COM, TDLib, `steam://`);
2. командная строка и конфиги;
3. Electron через Chrome DevTools Protocol (Discord, VS Code);
4. Windows UI Automation;
5. только картинка (OmniParser / UI-TARS, OpenCV).

Центральная идея: **растущая библиотека навыков** — изучил один раз, дальше код; при поломке переразведка.

### 13. Правки ТЗ и инструкции (23.11.2026)
- **Агент запускается в WSL (Ubuntu 24.04).** Добавлена архитектура «мозг в WSL, руки в Windows»:
