# Проект «Пилот»: агент, который сам управляет компьютером и записывает видео с живой озвучкой

## 1. Цель

Агент, которому ставят задачу обычным текстом («покажи, как настроить отдельные аудиодорожки в OBS»,
«создай пользователя на сайте X», «запиши ролик про Y»), и он:

1. Сам понимает, что происходит на экране, и принимает решения по ходу дела. Заранее прописанного сюжета нет.
2. Управляет любыми программами Windows, сайтами и Electron-приложениями.
3. Сам включает запись в OBS и комментирует свои действия живым голосом (ElevenLabs) прямо во время записи.
4. Учится: каждая разобранная программа превращается в набор готовых навыков (кода). В следующий раз
   этот навык выполняется мгновенно и без ИИ.

---

## 2. Ключевые идеи

### 2.1. «Изучил один раз — повторяю кодом»
ИИ нужен только там, где появляется новое: разобраться в незнакомой программе или выйти из
неожиданной ситуации. Всё, что уже изучено, выполняется обычным кодом: быстро, бесплатно и всегда одинаково.

### 2.2. Библиотека навыков растёт
Каждое изученное действие сохраняется как навык: функция, описание, проверка. Например:
`obs.start_recording()`, `obs.set_track(source, track)`, `discord.send_message(channel, text)`.
Со временем агент «знает» компьютер пользователя. Это обучение через накопление проверенного кода,
а не через дообучение нейросети.

### 2.3. Экран превращается в текст
Модель не разглядывает картинку на каждом шаге. Слой восприятия переводит экран в структурированный список:

```
[окно] OBS 33.0.0
  [1] кнопка "Начать запись"
  [2] кнопка "Настройки"
  [3] микшер: "Звук раб. стола" 0.0 dB, "Микро" 0.0 dB
[окно] Ошибка: "Устройство не найдено"  [4] кнопка "OK"
```

Решения по такому списку может принимать дешёвая текстовая модель (DeepSeek). Зрение нужно только там,
где программа не отдаёт структуру.

### 2.4. Два уровня мышления
- **Исполнитель** (быстрый, дешёвый): работает на каждом шаге. «Цель, экран, история → следующее действие».
- **Планировщик** (DeepSeek, flash-модель в режиме глубокого рассуждения): составляет план в начале,
  вызывается, когда исполнитель застрял, и проверяет итог. Скриншот он получает не картинкой, а текстом:
  наблюдение плюс разбор скриншота через OmniParser (см. п. 4.6).

Все модели во время работы агента — DeepSeek. Различаются только режимом: исполнитель работает быстро
без рассуждения, планировщик и компилятор — с глубоким рассуждением.

### 2.5. Пять входов в программу (от лучшего к худшему)
Для каждой программы выбирается самый надёжный доступный способ управления:

| № | Вход | Где применяется | Как управлять |
|---|------|-----------------|---------------|
| 1 | Собственное API программы | OBS (websocket), Office (COM), Telegram (TDLib), Steam (`steam://`) | Прямые вызовы |
| 2 | Командная строка и файлы настроек | Почти любая программа с конфигом | Аргументы запуска, правка JSON/ini |
| 3 | Electron / Chrome DevTools Protocol | Discord, VS Code и другие «браузеры внутри» | Playwright: DOM и сеть |
| 4 | Windows UI Automation | Обычные программы Windows | pywinauto: дерево окон и элементов |
| 5 | Только картинка | Игры, программы со своей отрисовкой | OmniParser / UI-TARS и образцы кнопок через OpenCV |

Для сайтов отдельно используется **перехват сетевых запросов**: кнопка на сайте почти всегда вызывает
внутренний JSON-API, и навык обращается к нему напрямую.

### 2.6. Живой голос, который маскирует задержки
На каждом шаге модель возвращает и действие, и реплику. Реплика сразу уходит в ElevenLabs в потоковом
режиме и звучит одновременно с действием. Пока агент говорит, он уже думает над следующим шагом,
поэтому пауз в ролике нет.

### 2.7. Самовосстановление
Навык сломался (программа обновилась, кнопку переименовали), и запускается повторная разведка только
для этого навыка. Он перекомпилируется, проходит проверку, и в библиотеке появляется новая версия.

### 2.8. Мозг в WSL, руки в Windows
Агент работает внутри **WSL (Ubuntu 24.04)**: там оркестратор, модели, библиотека навыков,
разведчик, компилятор и MCP-сервер. Но управлять он должен программами **Windows**: окнами, OBS,
звуком, экраном. Из Linux напрямую до них не дотянуться: UI Automation, глобальные горячие клавиши,
аудиоустройства и скриншоты рабочего стола доступны только из Windows.

Поэтому проект состоит из двух частей:
- **Мозг (WSL):** всё, что думает и хранит.
- **Мост (Windows):** небольшой сервис на Windows-Python, который ничего не решает, а только выполняет
  команды мозга: наблюдение через UIA, действия, скриншоты, проигрывание голоса, стоп-клавиша.

Мост тонкий и «тупой»: вся логика остаётся в WSL, а в Windows лежат только руки и глаза.

### 3.1. Где что работает: WSL и Windows

```
┌──────────────────── WSL (Ubuntu 24.04) ────────────────────┐      ┌──────────────── Windows 11 ────────────────┐
│                                                            │      │                                            │
│  оркестратор · исполнитель · планировщик · разведчик ·     │      │  WIN-BRIDGE (Windows Python 3.12)          │
│  компилятор · библиотека навыков · MCP-сервер ·            │ HTTP │   /observe   дерево UIA → список элементов │
│  генерация голоса (ElevenLabs) · проверка записей (ffmpeg) │◀────▶│   /act       клики, ввод, клавиши (UIA)    │
│                                                            │ JSON │   /screenshot снимок экрана / окна         │
│  Playwright ──── CDP ────────────────────────────────────────────▶│   /play      звук → VB-Cable               │
│  (Electron-программы и Chrome на Windows)                  │      │   /events    поток событий UIA             │
│                                                            │      │   стоп-клавиша Ctrl+Alt+Q                  │
│  obs-websocket клиент ──────── ws://localhost:4455 ──────────────▶│  OBS Studio                                │
│                                                            │      │  программы пользователя                    │
│  /mnt/d/Video/recordly  ◀──── файлы записей ─────────────────────│  D:\Video\recordly                         │
└────────────────────────────────────────────────────────────┘      └────────────────────────────────────────────┘
```

| Задача | Где | Как |
|--------|-----|-----|
| Логика агента, модели, навыки, MCP | WSL | Python 3.12 в `.venv` |
| Наблюдение и действия в Windows-программах (вход 4) | Windows-мост | pywinauto (UIA), вызывается из WSL по HTTP |
| Electron и браузер (вход 3) | WSL → Windows | Playwright из WSL подключается к Windows-программам по CDP |
| Сайты в режиме «Сделай» | WSL | Playwright с headless-браузером внутри WSL |
| Сайты в режиме «Покажи и запиши» | Windows | Chrome на Windows, управляемый по CDP из WSL: окно видно на рабочем столе и попадает в запись |
| OBS (вход 1) | WSL → Windows | obs-websocket напрямую из WSL |
| Конфиги и CLI Windows-программ (вход 2) | WSL | Файлы через `/mnt/c`, `/mnt/d`; запуск `.exe` из WSL через interop |
| Зрение (вход 5) | WSL | Скриншот берётся у моста, распознавание — в WSL |
| Генерация голоса | WSL | ElevenLabs API, поток аудиочанков |
| Проигрывание голоса | Windows-мост | Чанки из WSL → мост → устройство VB-Cable |
| Стоп-клавиша | Windows-мост | Глобальный хоткей; мост сразу прекращает действия и сообщает в WSL |
| Проверка записей | WSL | Полный ffmpeg из apt по пути `/mnt/d/Video/recordly` |

**Сеть.** В WSL включается режим **mirrored networking** (`%UserProfile%\.wslconfig`:
`[wsl2] networkingMode=mirrored`). Тогда `localhost` общий для WSL и Windows: мост, obs-websocket и
CDP-порты программ доступны из WSL по `localhost` без пробросов.

**Протокол моста.** HTTP + JSON на `127.0.0.1:8765`. Мост слушает только локальный адрес, каждый запрос
подписан общим токеном из переменной окружения `PILOT_BRIDGE_TOKEN` (одинаковой в WSL и Windows).
Поток событий UIA и аудиочанки идут через WebSocket на том же порту.

**Файлы.** Репозиторий лежит в файловой системе Linux (`~/pilot`), а не на `/mnt/c`: так в разы быстрее.
Мост — это отдельная папка `win_bridge/` того же репозитория. На Windows она запускается по пути
`\\wsl$\Ubuntu-24.04\home\<user>\pilot\win_bridge` или копируется скриптом развёртывания в
`%LOCALAPPDATA%\pilot-bridge\`.

**Зрение и видеокарта.** Видеокарта у пользователя AMD. Локальные модели зрения (OmniParser, UI-TARS) в WSL
на AMD работают только при поддержке ROCm для конкретной модели карты. Если поддержки нет, распознавание
выполняется на CPU (медленно) или переносится в мост на Windows через DirectML (ONNX Runtime).
Выбор фиксируется на этапе 9.

## 4. Компоненты

### 4.1. Слой восприятия и управления
- **Наблюдение**: собирает текстовое описание экрана из всех доступных источников (дерево UIA, DOM,
  OmniParser) и выдаёт единый список элементов с номерами.
- **События**: подписка на события Windows UI Automation (открылось окно, изменилось значение,
  появился диалог). Агент реагирует на событие, а не опрашивает экран постоянно.
- **Действия**: единый набор `click(id)`, `type(id, text)`, `select(id, value)`, `scroll(id, dir)`,
  `key(combo)`, `wait(condition)`, `call(skill, args)`. Каждый вход (1–5) реализует их по-своему.
- **Скриншоты** снимаются только по запросу планировщика или для режима «только картинка».
- Всё, что касается Windows-окон (UIA, события, скриншоты, клавиатура и мышь), выполняет Windows-мост.
  В WSL ему соответствует клиент `bridge_client.py` с тем же набором действий.

### 4.2. Разведчик
Вход: программа и цель («научиться менять дорожки источника в OBS»).
1. Определяет, какие входы доступны: ищет API и документацию, проверяет, Electron ли это, отдаёт ли
   программа дерево UIA, какие файлы конфигурации она меняет.
2. Выбирает лучший вход по таблице из п. 2.5.
3. Выполняет цель, записывая журнал: действия, изменения экрана, сетевые запросы (для сайтов и Electron)
   и изменения в файлах настроек (снимок «до» и «после»).

Выход: журнал разведки.

### 4.3. Компилятор и проверка
1. По журналу генерирует функцию-навык с параметрами (например, `set_track(source: str, track: int)`).
2. Генерирует проверку: как убедиться, что навык сработал (состояние элемента, ответ API,
   содержимое конфига).
3. Запускает навык и проверку. Ошибка уходит обратно в модель, код исправляется, и так по кругу до успеха.
4. Сохраняет навык в библиотеку.

### 4.4. Библиотека навыков
Каждый навык хранится в отдельной папке:

```
skills/obs/set_track/
  skill.py        # код
  manifest.json   # описание, параметры, вход (1–5), версия программы, дата
  check.py        # проверка результата
  log.jsonl       # история запусков: успех/ошибка
```

Пример `manifest.json`:
```json
{
  "name": "obs.set_track",
  "description": "Назначить аудиоисточнику OBS дорожки записи",
  "params": {"source": "string", "tracks": "int[]"},
  "entry": "api:obs-websocket",
  "app_version": "33.0.0",
  "version": 3
}
```

Вся библиотека автоматически публикуется как **MCP-сервер**: Claude Code, Cursor и любые агенты
вызывают навыки как обычные инструменты.

### 4.5. Исполнитель (цикл реального времени)
На каждом шаге получает: цель, план, текущее наблюдение, последние N шагов и список доступных навыков.
Возвращает:

```json
{
  "thought": "Открыто окно настроек, нужна вкладка Аудио",
  "do": {"action": "click", "id": 7},
  "say": "Переходим во вкладку «Аудио»",
  "expect": "открыта вкладка Аудио"
}
```

Правила:
- Если есть готовый навык под шаг, вызывается навык (`call`), а не клики.
- Если `expect` не сбылся 2 раза подряд, управление передаётся планировщику.
- Если за 3 шага нет прогресса к цели, тоже передаётся планировщику.

### 4.6. Планировщик
- В начале разбивает задачу на подцели.
- При вызове от исполнителя получает наблюдение, историю шагов и **текстовый разбор скриншота**,
  ставит диагноз и выдаёт новый план или одно конкретное действие.
- Разбор скриншота делается локально: мост снимает экран, OmniParser в WSL (или в мосту, см. п. 3.1)
  превращает его в список областей с подписями и координатами. Если используемая модель DeepSeek
  принимает изображения, скриншот дополнительно передаётся картинкой. Это включается флагом
  `planner_images` в конфиге.
- Если нужного навыка нет и задача повторяемая, отправляет программу к разведчику.
- В конце проверяет результат по скриншоту и состоянию.

### 4.7. Голос
- Реплика `say` сразу отправляется в ElevenLabs по потоковому API (модели Flash/Turbo) и начинает звучать,
  ещё не догенерировавшись.
- Голос проигрывается **на отдельное виртуальное аудиоустройство** (VB-Cable), которое в OBS заведено
  отдельным источником. Так голос агента попадает на свою дорожку, отдельно от звука системы.
- Генерация идёт в WSL, а проигрывание — на Windows: WSL передаёт аудиочанки мосту по WebSocket, и мост
  сразу выводит их в VB-Cable. Звук WSLg (PulseAudio) для этого не используется: он не позволяет выбрать
  нужное Windows-устройство.
- Очередь реплик: новая фраза не перебивает текущую, а встаёт следом. Устаревшие реплики выбрасываются.
- Частые фразы («секунду», «готово», «открываем настройки») кешируются файлами, чтобы не генерировать их повторно.

### 4.8. Запись
- OBS управляется через obs-websocket: старт и стоп записи, сцены, проверка, что идёт запись.
- Схема дорожек:
  - дорожка 1: звук системы;
  - дорожка 2: голос агента (VB-Cable);
  - дорожка 3: микрофон пользователя, если он участвует.
- После записи оркестратор автоматически проверяет файл: дорожки на месте и в каждой есть звук.

### 4.9. Оркестратор
- Принимает задачу и режим работы (см. п. 6).
- Ведёт цикл «наблюдение → решение → действие → голос».
- Ограничения: максимальное число шагов, время и бюджет на запросы к моделям.
- Ведёт полный журнал сессии: шаги, реплики, скриншоты в ключевых точках.

### 4.10. Безопасность (встроенная, не отключаемая)
- Глобальная горячая клавиша мгновенной остановки агента и записи. Её ловит Windows-мост: он сразу
  прекращает выполнять действия (даже если WSL не отвечает) и сообщает оркестратору.
- Мост слушает только `127.0.0.1` и принимает запросы только с токеном `PILOT_BRIDGE_TOKEN`.
- Белый список программ, в которых агенту разрешено действовать.
- Действия «удалить», «отправить», «оплатить», «опубликовать» требуют подтверждения пользователя.
- Пароли и ключи никогда не передаются модели. Ключи API лежат в переменных окружения, сессии
  сайтов хранятся локально в профиле браузера.

## 5. Модели и их роли

| Роль | Модель | Почему |
|------|--------|--------|
| Разработка самого проекта, сложная отладка | Claude Opus в Claude Code (подписка) | Инструмент разработчика, в работе агента не участвует |
| Планировщик (диагностика, план, проверка итога) | DeepSeek flash, глубокое рассуждение | Нужно рассуждать, скорость вторична |
| Исполнитель (каждый шаг) | DeepSeek flash, без рассуждения | Текстовая задача по списку элементов, дёшево и быстро |
| Компилятор навыков | DeepSeek flash, глубокое рассуждение | Генерация и починка кода по журналу, много итераций |
| Поиск элементов на картинке | OmniParser / UI-TARS (локально) | Бесплатно, обучены именно на интерфейсах |
| Голос | ElevenLabs (потоковый режим) | Живая озвучка с малой задержкой |

Модели подключаются через единый адаптер: роль → модель и режим рассуждения задаются в конфиге и
меняются одной строкой. Точное имя flash-модели DeepSeek и параметр включения рассуждения берутся из
актуальной документации DeepSeek API на момент разработки.

## 6. Режимы работы

**A. «Сделай»**: выполнить задачу максимально быстро. Используются навыки и API, видимость на экране
не важна, голос и запись выключены.

**B. «Покажи и запиши»**: ролик с живой озвучкой.
1. Оркестратор включает запись в OBS.
2. Планировщик составляет план показа.
3. Исполнитель выполняет шаги **видимо**: навыки вызываются в «показательной» версии, через интерфейс,
   а не через скрытый API, чтобы зритель видел действия. Каждый шаг сопровождается репликой.
4. Неожиданности (окна, ошибки) агент проходит сам и комментирует вслух.
5. Стоп записи и автоматическая проверка файла.

**C. «Изучи»**: разведка новой программы или сайта без выполнения задачи. Пользователь может
показать действия сам; разведчик записывает их и компилирует в навыки.

Поэтому у каждого навыка две реализации: **быстрая** (API) и **показательная** (через видимый интерфейс).

## 8. Этапы реализации и критерии готовности

| Этап | Что делаем | Готово, когда |
|------|------------|---------------|
| 0. WSL и мост | Mirrored networking, репозиторий в `~/pilot`, Windows-мост с `/observe`, `/act`, `/screenshot`, `/play`, стоп-клавиша, токен | Из WSL получен список элементов окна Блокнота, в него введён текст, сделан скриншот; стоп-клавиша обрывает серию действий |
| 1. Запись и голос | obs-websocket, ElevenLabs в потоковом режиме, VB-Cable, отдельная дорожка голоса | Скрипт сам записывает 30 с: в файле дорожка системы и дорожка голоса, обе со звуком |
| 2. Восприятие | Наблюдение через UIA и CDP в едином списке, подписка на события | Для OBS, Discord и Проводника выводится понятный список элементов с номерами |
| 3. Исполнитель | Цикл с DeepSeek, набор действий, `expect` | Задача «открой настройки аудио в OBS» выполняется без готового навыка |
| 4. Планировщик | DeepSeek в режиме рассуждения, текстовый разбор скриншота (OmniParser), передача управления при застревании | Агент сам закрывает неожиданное окно-ошибку и продолжает задачу |
| 5. Навыки и MCP | Формат навыка, библиотека, MCP-сервер | Claude Code вызывает `obs.set_track` как инструмент |
| 6. Разведчик и компилятор | Журнал разведки, генерация навыка, цикл проверки | Новый навык для незнакомой программы создаётся и проходит проверку без ручной правки |
| 7. Сайты | Перехват сетевых запросов, навыки на внутреннем API, сохранение сессий | Действие на сайте вызывается функцией без открытия браузера |
| 8. Режим «Покажи и запиши» | Показательные версии навыков, синхронизация голоса и действий | Агент по одной фразе-задаче записывает связный ролик с живой озвучкой |
| 9. Зрение для «закрытых» программ | OmniParser / UI-TARS, образцы кнопок | Агент выполняет простое действие в программе без дерева UIA |
| 10. Самовосстановление | Счётчик ошибок навыка, автоматическая переразведка | Сломанный навык сам перекомпилируется и снова проходит проверку |

Этап 0 — фундамент: без моста агент из WSL не видит и не трогает Windows.
Каждый этап даёт работающий результат сам по себе. Порядок выбран так, чтобы уже после этапа 3
агент сам что-то делал на экране, а после этапа 8 сам записывал ролики.

## 9. Стек

- **Где работает:** мозг — WSL (Ubuntu 24.04), мост — Windows 11.
- **Язык:** Python 3.12 с обеих сторон (в Ubuntu 24.04 он системный, на Windows уже установлен).
- **Мост (Windows):** FastAPI + uvicorn, pywinauto (UIA), `mss` (скриншоты), `sounddevice` (вывод в VB-Cable),
  `keyboard` (глобальная стоп-клавиша).
- **Мозг (WSL):** `httpx`/`websockets` (клиент моста), Playwright (CDP к Windows-программам и headless-браузер),
  obs-websocket (`obsws-python`), OpenCV, ffmpeg из apt.
- **Зрение:** OmniParser или UI-TARS локально (на видеокарте).
- **Модели:** только DeepSeek (OpenAI-совместимый API, клиент `openai`).
- **Голос:** ElevenLabs SDK (потоковый режим) в WSL, проигрывание — в мосту.
- **MCP:** FastMCP.
- **Хранение:** файлы навыков и JSONL-журналы, без базы данных.
